# 해석의뢰 앱 UX 설계 기준서

## 1. 사용자

이 문서는 업무정의서의 역할과 상태를 UX로 해석하는 기준이다. 사용자는 하나의 역할과 하나의 소속 부서를 가지며, 역할과 소속 부서는 세션에서 제공된다는 업무 전제를 사용한다. 실제 로그인, 로그아웃, 계정 관리, 세션 만료와 사용자·권한 운영은 아직 확정되지 않았으므로 업무 UX 범위에 포함하지 않는다.

| 사용자 | 업무상 위치 | 업무 UX에서 다루는 대상 |
|---|---|---|
| 의뢰자 | 해석이 필요한 문제를 의뢰하고 결과를 확인하는 기구설계 엔지니어 | 본인이 만든 의뢰와, 조회만 가능한 같은 소속 부서의 다른 의뢰자가 만든 의뢰 |
| 해석관리자 | 의뢰를 검토해 접수하고 해석담당자를 배정하는 사람 | 한 번 이상 제출된 전체 의뢰 |
| 해석담당자 | 배정된 의뢰의 해석을 수행하고 결과를 회신하는 사람 | 본인에게 배정된 의뢰 |

한 번도 제출하지 않은 의뢰(작성 중 및 제출 전에 취소한 의뢰)는 작성자만 볼 수 있다. 같은 부서 의뢰자는 다른 사람이 만든 의뢰를 조회만 할 수 있고, 업무 행위를 할 수 없다. 종료 상태(완료, 반려, 취소)는 모든 역할에서 조회만 한다.

## 2. 역할·권한·책임

| 역할 | 책임 | 할 수 있는 업무 행위 | 조회 범위 |
|---|---|---|---|
| 의뢰자 | 착수 가능한 의뢰서를 작성하고 결과를 확인한다 | 의뢰 작성·제출, 보완 후 재제출, 진행 중 변경 요청, 취소·취소 요청, 결과 재작업 요청, 결과 확인 | 자기 의뢰, 같은 소속 부서에서 만든 의뢰(조회만) |
| 해석관리자 | 의뢰를 검토해 접수하고 담당자를 배정한다 | 검토·해석 단계 보완 요청, 반려, 접수·배정, 재배정, 보류·재개, 취소 요청 승인·거절 | 전체 의뢰. 단, 한 번도 제출하지 않은 의뢰는 제외 |
| 해석담당자 | 해석을 수행하고 결과를 회신한다 | 해석 단계 보완 요청, 보류·재개, 진행 중 변경 수락·거절, 결과 등록 | 배정받은 의뢰 |

- 새 의뢰는 의뢰자만 만들 수 있다.
- 각 업무 행위는 업무정의서 3.2의 수행 가능 상태에서만 가능하다. 취소 요청이 대기 중이면 관리자의 취소 요청 승인·거절만 가능하다.
- 담당자와 관리자는 의뢰서 내용을 직접 고치지 않는다. 의뢰서 수정은 의뢰자가 가능한 상태에서 수행한다.

## 3. 역할별 사용자 여정

이 절은 역할별 목표, 업무를 시작하는 현재 처리 대상, 성공 기준과 역할별 여정을 정의한다. 현재 처리 대상은 역할이 다음 처리를 책임지거나 작업을 재개해야 하는 할 일이며, 조회 범위나 업무 행위 권한과는 구분한다. 화면·정보 구조는 후속 작업에서 다룬다.

| 역할 | 목표 | 업무 시작점: 현재 처리 대상 | 성공 기준 |
|---|---|---|---|
| 의뢰자 | 해석 목적, 대상 제품, 해석 조건을 빠짐없이 전달하여 해석담당자가 별도 재문의 없이 착수 여부를 판단할 수 있게 하고, 회신된 결과를 확인한다. | 작성 중인 의뢰를 이어 작성하거나, 보완 필요·해석 중 보완 필요 의뢰에 응답하거나, 결과 확인 필요 의뢰의 결과를 판단한다. | 제출할 때는 제출 조건을 충족한 의뢰서를 검토 대상으로 넘긴다. 보완·변경·취소·재작업처럼 본인에게 필요한 후속 행위는 해당 상태에서 요청 또는 재제출한다. 업무의 최종 성공은 결과를 확인하여 의뢰가 완료 상태가 되는 것이다. |
| 해석관리자 | 제출된 의뢰를 검토하여 접수 가능 여부를 판단하고, 접수한 의뢰에 담당자를 배정하며, 관리자의 처리가 필요한 취소 요청·해석 단계 확인·보류를 처리한다. | 검토 중, 취소 요청 대기, 해석 진행 중(관리자 확인 대기), 관리자가 보류한 의뢰를 처리한다. | 검토 중 의뢰마다 보완 요청, 반려, 또는 담당자를 지정한 접수·배정 중 하나로 검토 처리가 끝난다. 취소 요청 대기는 승인 또는 거절로 처리한다. 관리자 확인 대기는 해석 계속·담당자 배정 또는 재보완 요청으로 처리한다. |
| 해석담당자 | 배정된 의뢰의 해석을 수행하고 결과를 회신한다. | 본인에게 배정된 해석 진행 중 의뢰(관리자 확인 대기 제외), 진행 중 변경 수락 대기 의뢰, 본인이 보류한 의뢰를 처리한다. | 해석을 계속할 수 없으면 정의된 보완 요청 또는 보류로 처리하고, 진행 중 변경은 수락 또는 거절한다. 해석이 끝난 의뢰에는 결과 요약을 등록하여 의뢰자가 확인할 수 있는 결과 확인 필요 상태로 만든다. |

### 현재 처리 대상과 관리·조회 대상 적용 원칙

- 의뢰자의 현재 처리 대상은 작성 중, 보완 필요, 해석 중 보완 필요, 결과 확인 필요 의뢰다.
- 관리자의 현재 처리 대상은 검토 중, 취소 요청 대기, 해석 진행 중(관리자 확인 대기), 관리자가 보류한 의뢰다.
- 담당자의 현재 처리 대상은 본인에게 배정된 해석 진행 중 의뢰(관리자 확인 대기 제외), 진행 중 변경 수락 대기 의뢰, 본인이 보류한 의뢰다.
- 취소 요청 대기 의뢰는 관리자에게만 현재 처리 대상으로 들어간다. 그동안 의뢰자와 담당자는 업무 행위를 할 수 없다.
- 관리·조회 대상은 현재 처리 대상이 아니더라도 역할의 조회 범위 안에서 열람하거나, 업무정의서 3.2가 허용하는 상태에서 업무 행위를 할 수 있는 의뢰다. 이 대상은 할 일 목록에 자동으로 들어가지 않는다.

### 의뢰자 정상 여정 (1.2)

이 여정은 보완, 반려, 보류, 진행 중 변경, 취소, 결과 재작업이 없는 정상 경로만 다룬다. 의뢰자는 의뢰서 작성부터 결과 확인까지의 진행 상태를 조회할 수 있으며, 할 일에는 의뢰자가 다음 처리를 해야 하는 상태만 들어간다.

| 순서 | 의뢰자의 상태와 다음 행동 | 인계와 다음 상태 | 정상 경로의 완료 기준 |
|---|---|---|---|
| 1. 작성 시작·계속 | 의뢰자는 새 의뢰를 만들거나 `작성 중` 의뢰를 이어 작성한다. | `작성 중`은 의뢰자의 현재 처리 대상이다. 제출 전 의뢰는 작성자만 볼 수 있다. | 의뢰 대상을 확정할 준비가 된다. |
| 2. 의뢰 대상 확정 | 의뢰자는 제품 분류, 해석유형과 해당되는 해석 범위·냉각 방식을 확정한다. | 의뢰 대상이 잠기고 의뢰번호가 발급되며, 해석유형에 맞는 조건 구성이 정해진다. 의뢰는 계속 `작성 중`이다. | 확정된 대상에 맞춰 의뢰서·조건·Case를 준비할 수 있다. |
| 3. 의뢰서·조건·Case 준비 | 의뢰자는 의뢰 내용, 해석 제품, 활성 조건을 준비하고 형상과 활성 조건 패키지를 Case로 구성한다. | `작성 중`에서 제출 조건을 충족할 때까지 의뢰자가 계속 처리한다. | 최소 1개 이상의 Case와 제출 조건을 충족한 의뢰서가 준비된다. |
| 4. 제출 | 의뢰자는 제출 조건을 충족한 의뢰서를 제출한다. | 상태가 `검토 중`으로 바뀌고, 관리자가 다음 처리자다. 의뢰자는 검토 결과를 기다리며 진행 상태를 조회한다. | 제출한 의뢰가 관리자 검토 대상으로 인계된다. |
| 5. 접수·배정 후 해석 진행 | 정상 경로에서는 관리자가 의뢰를 접수하고 담당자를 배정한다. 의뢰자는 `해석 진행 중` 의뢰의 진행 상태를 조회한다. | 상태가 `해석 진행 중`으로 바뀌고, 배정된 해석담당자가 다음 처리자다. | 배정된 담당자가 해석을 수행할 수 있다. |
| 6. 결과 수신 | 담당자가 결과 요약을 등록하면 의뢰자는 결과를 확인할 차례가 된다. | 상태가 `결과 확인 필요`로 바뀌며, 의뢰자의 현재 처리 대상이 된다. | 의뢰자가 결과 요약을 바탕으로 결과를 확인할 준비가 된다. |
| 7. 결과 확인 | 의뢰자는 등록된 현재 결과를 확인한다. | 의뢰자가 결과 확인을 하면 상태가 `완료`로 바뀌고, 이후에는 조회만 가능하다. | 의뢰가 완료 상태에 도달한다. |

정상 경로의 인계 순서는 `의뢰자(작성·제출) → 관리자(접수·배정) → 해석담당자(결과 등록) → 의뢰자(결과 확인)`이다. 각 인계 뒤에는 다음 처리자가 행동할 때까지 이전 처리자는 진행 상태를 조회한다. 보완·반려·보류·변경·취소·결과 재작업으로 갈라지는 경우는 1.3에서 정의한다.

### 의뢰자 예외 여정 (1.3)

예외 여정에서도 의뢰자는 의뢰서 내용을 직접 고칠 수 있는 상태에서만 고치고, `해석 진행 중`의 내용 변경은 진행 중 변경 요청으로만 한다. 보완 후 재제출은 내용이 바뀌지 않아도 할 수 있다. 제출, 재제출, 진행 중 변경 수락 때마다 의뢰서의 새 버전이 남는다. 아래의 `조회·대기`는 의뢰자의 현재 처리 대상이나 할 일이 아니며, 다음 처리자의 결정을 기다리며 상태와 이력을 열람하는 대상이라는 뜻이다.

#### 보완과 보류

| 시작 상황 | 의뢰자의 행동 | 인계와 다음 상태 | 의뢰자에게 남는 상태 |
|---|---|---|---|
| 관리자가 `검토 중`에 검토 단계 보완을 요청 | 상태가 `보완 필요`가 되면 의뢰자는 의뢰서를 고치거나 그대로 재제출한다. | 재제출하면 `검토 중`으로 돌아가며, 관리자가 다음 처리자다. | `보완 필요`는 의뢰자의 현재 처리 대상이다. 재제출 뒤에는 조회·대기한다. |
| 배정된 담당자가 `해석 진행 중`에 해석 단계 보완을 요청 | 상태가 `해석 중 보완 필요`가 되면(담당자 요청) 의뢰자는 의뢰서를 고치거나 그대로 재제출한다. | 재제출하면 `해석 진행 중`으로 돌아간다. 재배정이 없었다면 보완을 요청한 담당자가 해석을 이어서 수행한다. 재배정이 있었다면 재제출 뒤 처리자는 `G-31`이 확정될 때까지 정하지 않는다. | `해석 중 보완 필요`는 의뢰자의 현재 처리 대상이다. 재제출 뒤에는 담당자의 해석을 조회·대기한다. |
| 관리자가 `해석 진행 중`에 해석 단계 보완을 요청 | 상태가 `해석 중 보완 필요`가 되면(관리자 요청) 의뢰자는 의뢰서를 고치거나 그대로 재제출한다. | 재제출하면 `해석 진행 중(관리자 확인 대기)`가 되며, 관리자가 다음 처리자다. | 재제출 뒤에는 조회·대기한다. 관리자가 결정하기 전에는 의뢰자가 진행 중 변경이나 취소 요청을 할 수 없다. |
| 관리자가 확인 대기인 재제출을 확인 | 의뢰자는 추가 행동 없이 관리자의 결정을 조회·대기한다. | 관리자는 해석을 계속할 담당자를 배정해 일반 `해석 진행 중`으로 넘기거나, 재보완을 요청해 `해석 중 보완 필요`로 돌린다(관리자 요청). | 전자이면 새로 지정된 담당자가 다음 처리자이고, 후자이면 의뢰자가 다시 현재 처리자가 된다. 관리자가 배정하는 담당자는 기존 담당자와 같을 수 있다. |
| 배정 담당자 또는 관리자가 일정 등의 사유로 보류 | 의뢰자는 `보류` 의뢰를 조회·대기한다. 의뢰자는 재개, 의뢰서 수정, 진행 중 변경을 할 수 없다. 대기 중인 요청이 없을 때의 취소 요청만 예외로 할 수 있다. | 보류한 사람 또는 관리자가 재개하면 `해석 진행 중`이 되어 해석을 이어서 할 처리자에게 인계된다. | `보류`는 의뢰자의 현재 처리 대상이 아니다. 재개 전까지는 조회·대기 대상이다. |

검토 단계 보완은 관리자 검토로 돌아가고, 재배정이 없는 담당자 요청 해석 단계 보완은 담당자 해석으로 돌아간다. 반면 관리자 요청 해석 단계 보완은 반드시 관리자 확인 대기를 거친다. 정보 부족은 보류가 아니라 보완 요청으로 처리한다.

담당자가 보류한 의뢰는 관리자 재배정 뒤 새 담당자가 재개할 수 있으며, 이전 담당자는 더 이상 해당 의뢰를 보거나 재개할 수 없다. 관리자가 보류한 의뢰는 재배정해도 관리자의 보류로 남는다.

#### 진행 중 변경

| 시작 상황 | 의뢰자의 행동 | 인계와 다음 상태 | 의뢰자에게 남는 상태 |
|---|---|---|---|
| 대기 중인 요청이 없는 일반 `해석 진행 중` | 의뢰자는 제출 조건을 충족한 변경 의뢰서와 변경 사유로 진행 중 변경을 요청한다. | 상태는 `해석 진행 중`으로 유지되고 배정 담당자가 변경 수락·거절의 다음 처리자다. | 변경 요청이 대기하는 동안 의뢰자는 조회·대기한다. 취소 요청을 동시에 만들 수 없다. |
| 담당자가 변경을 수락 | 의뢰자는 결정 결과를 조회한다. | 변경 의뢰서가 새 버전으로 남고 `해석 진행 중`에서 담당자가 해석을 계속한다. | 의뢰자는 일반 진행 상태의 허용 범위에서만 후속 요청을 할 수 있다. |
| 담당자가 변경을 거절 | 의뢰자는 거절 사유와 원래 의뢰서를 조회한다. | 원래 의뢰서로 `해석 진행 중`이 계속되고 담당자가 해석을 이어서 수행한다. | 의뢰자는 일반 진행 상태의 허용 범위에서만 후속 요청을 할 수 있다. |

`해석 진행 중(관리자 확인 대기)`에서는 진행 중 변경 요청을 시작할 수 없다. 변경 요청이 대기 중인 동안에는 담당자가 먼저 수락·거절해야 하며, 그 전에는 해석 단계 보완 요청과 결과 등록도 진행되지 않는다.

변경 요청이 대기 중이어도 보류는 할 수 있다. 이 경우 변경 요청은 대기한 채로 남으며, 재개한 뒤 담당자가 수락하거나 거절한다.

진행 중 변경 요청이 대기한 상태에서 재배정되면 수락·거절 처리자는 `G-30`이 확정될 때까지 정하지 않는다.

#### 취소·반려와 결과 재작업

| 시작 상황 | 의뢰자의 행동 | 인계와 다음 상태 | 의뢰자에게 남는 상태 |
|---|---|---|---|
| `작성 중`, `검토 중`, `보완 필요` | 의뢰자는 직접 취소한다. | 상태가 `취소`로 바뀌며 종료한다. | 이후에는 조회만 한다. |
| 대기 중인 요청이 없는 일반 `해석 진행 중`, `해석 중 보완 필요`, `보류` | 의뢰자는 사유를 남겨 취소 요청을 한다. | 상태는 유지되지만 취소 요청은 관리자 승인 대기가 되고, 관리자가 유일한 다음 처리자다. | 요청이 대기하는 동안 의뢰자는 조회·대기만 한다. 재제출, 보완 요청, 보류·재개, 재배정, 결과 등록과 의뢰서 수정을 포함한 다른 업무 행위는 할 수 없다. |
| 관리자가 취소 요청을 승인 또는 거절 | 의뢰자는 결정 결과를 조회한다. | 승인하면 `취소`로 종료한다. 거절하면 요청 전 상태로 그대로 돌아가 해당 상태의 다음 처리자가 처리를 이어 간다. | 승인 뒤에는 조회만 한다. 거절 뒤에는 요청 전 상태의 규칙을 다시 따른다. |
| 관리자가 `검토 중` 의뢰를 반려 | 의뢰자는 반려 사유를 조회한다. | 상태가 `반려`로 바뀌며 종료한다. | 이후에는 조회만 한다. |
| `결과 확인 필요` | 의뢰자는 현재 결과를 확인한 뒤 결과를 확인하거나, 사유를 남겨 결과 재작업을 요청한다. | 결과 확인은 `완료`로 종료한다. 재작업 요청은 `해석 진행 중`으로 돌아가며 같은 담당자가 다음 처리자다. | 결과 재작업은 결과 확인과 다른 행동이다. 재작업 요청 뒤에는 같은 담당자의 해석과 다음 결과 등록을 조회·대기한다. |

`결과 확인 필요`에서는 취소와 취소 요청을 할 수 없다. 결과를 다시 등록하면 회차별 결과가 쌓이고 마지막 결과가 현재 결과가 되며, 의뢰자는 다시 결과 확인 또는 결과 재작업 요청을 판단한다.

#### 의뢰자의 조회·대기 경계

| 상태 또는 대기 | 다음 처리자 | 의뢰자의 처리 위치 |
|---|---|---|
| `검토 중` | 관리자 | 조회·대기 대상 |
| 일반 `해석 진행 중` | 배정 담당자 | 조회 대상이다. 대기 중인 요청이 없을 때만 진행 중 변경 또는 취소 요청을 시작할 수 있다. |
| `보류` | 보류한 사람 또는 관리자 | 조회·대기 대상이다. 재개·수정·진행 중 변경은 할 수 없고, 대기 중인 요청이 없을 때의 취소 요청만 가능하다. |
| `해석 진행 중(관리자 확인 대기)` | 관리자 | 조회·대기 대상이다. 관리자 결정 전에는 진행 중 변경과 취소 요청을 할 수 없다. |
| 취소 요청 대기 | 관리자 | 조회·대기 대상이며, 관리자의 승인·거절 외의 업무 행위는 할 수 없다. |
| `완료`, `반려`, `취소` | 없음 | 종료 상태로 조회만 한다. |

### 관리자 상세 여정 (1.4)

관리자는 한 번 이상 제출된 전체 의뢰를 조회하며, 다음 처리를 책임지는 `검토 중`, 취소 요청 대기, `해석 진행 중(관리자 확인 대기)`, 관리자가 보류한 의뢰를 할 일로 처리한다. 한 번도 제출하지 않은 의뢰와 제출 전 취소 의뢰는 관리자 조회 범위에 없다. 관리자는 의뢰서 내용을 직접 고치지 않으며, 아래 여정의 판단 기준이나 사유 코드 목록은 업무정의서의 검토 대상 규칙을 그대로 따른다.

#### 검토와 접수·배정

`검토 중`은 제출 또는 검토 단계 재제출 뒤 관리자의 현재 처리 대상이다. 관리자는 의뢰서와 이전 버전 대비 변경 내용을 보고, 다음 세 가지 중 하나로 검토를 끝낸다.

| 관리자의 결정 | 필수 기록 | 인계와 다음 상태 |
|---|---|---|
| 검토 단계 보완 요청 | 사유 코드, 설명 | `보완 필요`가 되며 의뢰자가 다음 처리자다. 의뢰자가 재제출하면 다시 `검토 중`으로 돌아와 관리자가 처리한다. |
| 반려 | 사유 코드, 설명 | `반려`로 종료하며 의뢰자는 반려 사유를 조회만 한다. |
| 접수·배정 | 해석담당자 | `해석 진행 중`이 되며 배정된 담당자가 다음 처리자다. 의뢰자는 진행 상황을 조회한다. |

관리자는 보완 요청과 반려에 필요한 사유 코드와 설명을 남기지만, 코드 값의 선택 기준을 이 여정에서 새로 정하지 않는다. 접수·배정 뒤에는 의뢰자와 배정된 담당자가 영향을 받는 사람으로 인계된다.

#### 해석 진행의 관리 개입

일반 `해석 진행 중`은 담당자가 주로 처리하는 상태지만, 관리자는 조회하고 아래의 관리 행위를 할 수 있다. 취소 요청이 대기 중이면 이 표의 행위를 할 수 없으며, 관리자 승인·거절만 처리한다.

| 시작 상태와 조건 | 관리자의 행동 | 인계와 상태 |
|---|---|---|
| 대기 중인 요청과 관리자 확인 대기가 없는 `해석 진행 중` | 정보 부족이면 해석 단계 보완을 요청하고 사유 코드와 설명을 남긴다. | `해석 중 보완 필요`가 되고 의뢰자가 보완·재제출의 다음 처리자다. 관리자가 요청한 보완의 재제출은 관리자 확인 대기로 돌아온다. |
| 일반 `해석 진행 중`, `해석 중 보완 필요`, `보류` | 현재 담당자와 다른 새 담당자 및 사유를 지정해 재배정한다. | 상태는 유지한다. 일반 진행 상태에서는 새 담당자가 다음 처리자가 된다. 진행 중 변경 요청이 대기 중인 재배정 뒤 그 요청의 수락·거절 처리자는 `G-30`이 확정될 때까지 정하지 않는다. 해석 중 보완 필요에서는 의뢰자의 재제출을 기다린다. 보류에서는 보류의 성격과 재개 규칙을 유지한다. |
| 관리자 확인 대기를 제외한 `해석 진행 중` | 일정 등 보완과 다른 사유로 보류하고 사유 코드와 설명을 남긴다. | `보류`가 된다. 관리자가 보류한 의뢰는 관리자의 현재 처리 대상이며, 의뢰자와 담당자는 재개를 기다린다. |
| `보류` | 관리자가 재개한다. | `해석 진행 중`으로 돌아가 현재 배정 담당자가 다음 처리자다. 담당자가 보류했던 의뢰도 관리자가 재개할 수 있다. |

담당자가 보류한 의뢰를 재배정하면 새 담당자가 보류를 이어받아 재개할 수 있고, 이전 담당자는 더 이상 그 의뢰를 보거나 재개할 수 없다. 관리자가 보류한 의뢰는 재배정해도 관리자의 보류로 남으므로, 관리자가 재개하기 전에는 새 담당자가 해석을 시작하지 않는다.

#### 관리자 요청 보완의 확인

관리자가 요청한 해석 단계 보완을 의뢰자가 재제출하면 `해석 진행 중(관리자 확인 대기)`가 되어 관리자의 현재 처리 대상이 된다. 이 대기 동안 담당자는 해석·결과 등록을 할 수 없고 의뢰자는 진행 중 변경·취소 요청을 할 수 없다. 관리자는 다음 둘 중 하나로만 확인을 끝낸다.

| 관리자의 확인 결정 | 필수 기록 | 인계와 다음 상태 |
|---|---|---|
| 해석 계속·담당자 배정 | 해석을 계속할 담당자 | 일반 `해석 진행 중`으로 바뀌며 지정 담당자가 다음 처리자다. 기존 담당자를 다시 지정할 수도 있다. |
| 재보완 요청 | 사유 코드, 설명 | `해석 중 보완 필요`가 되며 의뢰자가 다시 보완·재제출할 차례다. |

관리자 확인 대기에서는 일반 재배정, 보류, 새 해석 단계 보완 요청을 처리하지 않는다. 이 단계의 처리 책임은 특정 보완 요청자에게 고정하지 않고 관리자 역할에 둔다.

#### 취소 요청 처리

의뢰자가 일반 `해석 진행 중`, `해석 중 보완 필요`, `보류`에서 취소 요청을 하면 상태는 유지한 채 취소 요청 대기가 되고, 이는 관리자의 현재 처리 대상이다. 이 대기 동안에는 관리자의 승인·거절 외에 누구도 다른 업무 행위나 의뢰서 수정을 할 수 없다.

| 관리자의 결정 | 입력 또는 이력 | 인계와 결과 |
|---|---|---|
| 승인 | 자동 이력 | `취소`로 종료한다. 보류 중이었다면 보류 정보도 함께 지운다. 알림 초안의 대상은 의뢰자와 배정된 담당자다. |
| 거절 | 거절 사유, 자동 이력 | 요청 전 상태를 유지하고, 요청 전 상태의 다음 처리자가 이어서 처리한다. 이력에 거절과 사유를 남긴다. |

의뢰자가 `작성 중`, `검토 중`, `보완 필요`에서 직접 취소한 의뢰와 `완료`, `반려`, `취소` 상태는 관리자에게 처리 할 일이 없으며 조회만 한다.

#### 관리자 처리·조회 경계

| 상태 또는 대기 | 관리자의 위치 |
|---|---|
| `검토 중` | 검토·보완 요청·반려·접수·배정 중 하나를 처리하는 현재 처리 대상 |
| 취소 요청 대기 | 승인 또는 거절을 처리하는 현재 처리 대상. 그 밖의 업무 행위는 차단됨 |
| `해석 진행 중(관리자 확인 대기)` | 해석 계속·담당자 배정 또는 재보완 요청을 처리하는 현재 처리 대상 |
| 관리자가 보류한 `보류` | 재개할 때까지 현재 처리 대상 |
| 일반 `해석 진행 중`, `해석 중 보완 필요`, 담당자가 보류한 `보류` | 관리·조회 대상. 수행 가능 상태이면 해석 단계 보완 요청·재배정·보류·재개를 할 수 있으나 할 일 목록에는 자동으로 들어가지 않음 |
| `결과 확인 필요` | 관리·조회 대상. 의뢰자의 결과 확인 또는 재작업 요청을 기다리며 관리자의 업무 행위는 없음 |
| `작성 중`, 제출 전 `취소` | 조회·처리 대상 아님 |
| `완료`, `반려`, `취소` | 조회만 가능 |

### 담당자 상세 여정 (1.5)

담당자는 자신에게 배정된 의뢰를 조회하고 해석을 수행해 결과를 회신한다. 담당자의 현재 처리 대상은 본인에게 배정된 일반 `해석 진행 중`, 진행 중 변경 수락 대기, 본인이 보류한 의뢰다. 실제 해석 방법, 메시, 솔버와 수렴 판단은 이 업무 UX 범위 밖이며, 담당자는 의뢰서 내용을 직접 고치지 않는다.

#### 배정 수신과 해석 진행

관리자의 접수·배정, 관리자 확인 뒤 해석 계속·담당자 배정, 또는 결과 재작업 요청으로 담당자에게 일반 `해석 진행 중` 의뢰가 인계된다. 이 의뢰는 담당자의 현재 처리 대상이며, 담당자는 의뢰서와 이전 버전 대비 변경 내용을 확인해 해석을 진행한다. 결과 재작업 요청으로 돌아온 경우에도 같은 담당자가 다음 처리자이며, 이전 결과 회차는 남고 마지막 등록 결과가 현재 결과가 된다.

`해석 진행 중(관리자 확인 대기)`은 담당자가 배정된 의뢰라도 현재 처리 대상이 아니다. 담당자는 상태와 이력을 조회할 수 있으나, 관리자가 해석 계속·담당자 배정 또는 재보완 요청을 처리하기 전에는 해석을 진행하거나 결과를 등록할 수 없다.

#### 해석 단계 보완 요청

| 시작 상태와 조건 | 담당자의 행동 | 인계와 다음 상태 |
|---|---|---|
| 대기 중인 요청과 관리자 확인 대기가 없는 일반 `해석 진행 중` | 정보가 부족하면 해석 단계 보완을 요청하고 사유 코드와 설명을 남긴다. 해석을 멈춘다. | `해석 중 보완 필요`가 되며 의뢰자가 보완·재제출의 다음 처리자다. 담당자 요청 보완을 의뢰자가 재제출하면 일반 `해석 진행 중`으로 돌아가 담당자가 해석을 이어서 수행한다. |
| 관리자가 요청한 해석 단계 보완의 재제출 뒤 | 담당자는 관리자 확인의 진행 상황을 조회한다. | `해석 진행 중(관리자 확인 대기)`에서는 담당자가 보완 요청, 해석 진행, 결과 등록을 할 수 없다. 관리자가 해석 계속·담당자 배정하면 지정 담당자가 다시 처리한다. |

정보 부족은 보류가 아니라 보완 요청으로 처리한다. 담당자가 보완을 요청한 뒤 관리자가 재배정할 수 있으나, 재배정 뒤 의뢰자가 재제출했을 때 원 요청 담당자와 새 담당자 중 누가 해석을 이어받는지는 `G-31`이 확정될 때까지 정하지 않는다.

#### 진행 중 변경 요청 처리

의뢰자가 일반 `해석 진행 중`에서 진행 중 변경을 요청하면 상태는 유지되지만, 배정 담당자는 변경 수락·거절을 처리하는 현재 처리자가 된다. 담당자는 변경 의뢰서, 변경 사유와 이전 의뢰서의 차이를 확인해 다음 중 하나를 처리한다.

| 담당자의 결정 | 필수 입력 | 인계와 결과 |
|---|---|---|
| 수락 | 없음 | 변경 의뢰서가 새 버전으로 남고 일반 `해석 진행 중`에서 담당자가 해석을 계속한다. 의뢰자에게 결정 결과를 알린다. |
| 거절 | 거절 사유 | 원래 의뢰서로 일반 `해석 진행 중`을 계속하며 담당자가 해석을 이어서 수행한다. 제안된 변경 의뢰서와 거절 사유는 이력에 남고, 의뢰자에게 결정 결과를 알린다. |

변경 요청이 대기 중이면 담당자는 먼저 수락 또는 거절해야 해석 단계 보완을 요청할 수 있으며, 결과 등록도 할 수 없다. 보류는 가능하고 변경 요청은 대기한 채 남으며, 재개 뒤 담당자가 수락 또는 거절한다. 이 대기 중 재배정 뒤의 수락·거절 처리자는 `G-30` 확인 전까지 정하지 않는다.

#### 보류·재개와 재배정

| 시작 상태와 조건 | 담당자의 행동 또는 위치 | 인계와 다음 상태 |
|---|---|---|
| 관리자 확인 대기를 제외한 `해석 진행 중` | 일정 등 보완과 다른 사유로 보류하고 사유 코드와 설명을 남긴다. 진행 중 변경 요청이 대기 중이어도 보류할 수 있다. | `보류`가 되며 보류한 담당자의 현재 처리 대상이 된다. 의뢰자와 관리자는 보류 상태를 조회한다. |
| 본인이 보류한 `보류` | 담당자가 재개한다. | 일반 `해석 진행 중`으로 돌아가 같은 담당자가 해석을 다시 처리한다. |
| 관리자가 보류한 `보류` | 담당자는 조회·대기하며 재개할 수 없다. | 관리자가 재개하면 일반 `해석 진행 중`으로 돌아가 현재 배정 담당자가 다음 처리자다. |
| 관리자가 재배정한 의뢰 | 기존 담당자는 더 이상 다음 처리를 책임지지 않는다. | 일반 진행 상태에서는 새 담당자가 처리 대상이 된다. 담당자가 보류한 의뢰를 재배정한 경우에는 새 담당자가 보류를 이어받아 재개할 수 있고, 이전 담당자는 더 이상 해당 의뢰를 보거나 재개할 수 없다. |

#### 취소 요청과 결과 등록

취소 요청이 대기 중인 의뢰는 관리자의 승인·거절만 가능하다. 담당자는 해석, 보완 요청, 보류·재개, 결과 등록 등 어떤 업무 행위도 할 수 없으며 관리자의 결정을 조회·대기한다. 승인되면 `취소`로 종료하고, 거절되면 요청 전 상태의 규칙에 따라 다음 처리자가 업무를 이어 간다.

| 시작 상태와 조건 | 담당자의 행동 | 인계와 다음 상태 |
|---|---|---|
| 대기 중인 요청이 없는 일반 `해석 진행 중` | 해석이 끝나면 결과 요약을 등록한다. | `결과 확인 필요`가 되고 의뢰자가 결과 확인 또는 재작업 요청의 다음 처리자다. 담당자는 결과 확인을 조회한다. |
| `결과 확인 필요`에서 의뢰자가 재작업 요청 | 담당자는 재작업 요청과 사유를 확인한다. | 일반 `해석 진행 중`으로 돌아가 같은 담당자가 해석을 다시 진행한다. |
| `결과 확인 필요`에서 의뢰자가 결과 확인 | 담당자는 완료 결과를 조회한다. | `완료`로 종료하며 이후에는 조회만 한다. |

#### 담당자 처리·조회 경계

| 상태 또는 대기 | 담당자의 위치 |
|---|---|
| 본인에게 배정된 일반 `해석 진행 중` | 해석 진행, 해석 단계 보완 요청, 보류, 결과 등록을 수행하는 현재 처리 대상. 대기 중인 요청이 있으면 허용된 행동만 할 수 있음 |
| 진행 중 변경 수락 대기 | 수락 또는 거절을 처리하는 현재 처리 대상. 보류만 병행할 수 있고, 보완 요청과 결과 등록은 할 수 없음 |
| 본인이 보류한 `보류` | 재개할 때까지 현재 처리 대상 |
| `해석 진행 중(관리자 확인 대기)`, 관리자가 보류한 `보류`, 취소 요청 대기 | 조회·대기 대상. 담당자 업무 행위는 할 수 없음 |
| `해석 중 보완 필요` | 의뢰자의 재제출을 기다리는 조회 대상. 관리자가 재배정할 수 있음 |
| `결과 확인 필요` | 의뢰자의 결과 확인 또는 재작업 요청을 기다리는 조회 대상 |
| `완료`, 배정 후 `취소` | 종료 상태로 조회만 가능 |
| `반려`, 배정 전 `취소` | 담당자에게 배정 이력이 없으므로 조회·처리 대상 아님 |

### 세 역할의 인계와 대기 대조 (1.6)

아래 대조는 앞선 세 역할 여정의 상태 변화마다 수행자, 다음 처리자와 대기·차단 역할이 하나로 읽히는지 확인한 결과다. 업무 행위의 수행 가능 상태는 업무정의서 3.2를 우선하며, 같은 상태라도 대기 요청의 종류에 따라 다음 처리자가 달라지는 경우를 분리한다.

|---|---|---|---|
| 제출 또는 검토 단계 재제출 | 의뢰자 | `검토 중`으로 바뀌며 관리자가 검토한다. | 의뢰자는 검토 결과를 조회·대기한다. |
| 검토 단계 보완 요청 | 관리자 | `보완 필요`가 되며 의뢰자가 보완·재제출한다. | 관리자는 재제출 뒤 검토를 이어서 처리한다. |

| 접수·배정 | 관리자 | 일반 `해석 진행 중`이 되며 배정 담당자가 해석을 시작한다. | 의뢰자는 진행 상황을 조회한다. |

| 관리자 요청 해석 단계 보완 | 관리자 | `해석 중 보완 필요`가 되며 의뢰자가 재제출한다. | 재제출 뒤 `해석 진행 중(관리자 확인 대기)`가 되어 관리자가 해석 계속·담당자 배정 또는 재보완 요청을 처리한다. 담당자는 해석·결과 등록을, 의뢰자는 변경·취소 요청을 할 수 없다. |

| `결과 확인 필요` | 의뢰자 | 담당자와 관리자는 결과 확인 또는 재작업 요청을 기다리며 조회한다. |
| `완료`, `반려`, `취소` | 없음 | 종료 상태로 조회만 한다. 단, 담당자는 배정 이력이 있는 의뢰만 조회한다. |

`G-30`과 `G-31`은 재배정과 대기 요청이 겹치는 두 경우의 다음 처리자를 아직 확정하지 않은 항목이다. 이 두 경우를 제외하면 각 인계 지점의 수행자·다음 처리자·대기 역할은 세 역할 여정과 업무정의서 3.2~3.5에서 일치한다.

## 4. 보류 항목 적용 경계

설치 조건 세부와 CAD 전달 방식은 `확정 필요`이므로 입력 구조나 전달 수단을 이 기준서에서 정하지 않는다. 그 밖의 보류 항목은 상태와 책임만 표현하며, 임시 값, 검증 규칙, 인증 방식, 첨부 제약을 가정하지 않는다. 자세한 근거와 처리 원칙은 `docs/spec-gaps.md`의 `UX 착수 보류 항목 구분 (0.2)`를 따른다.

## 5. 화면 범위 및 정보 구조

### 공통 탐색 구조와 역할별 첫 화면 (2.1)

이 절은 역할별 업무를 어디에서 시작하고 찾는지의 책임만 정의한다. 여기의 `홈`, `내 할 일`, `의뢰함`, `의뢰 상세`는 탐색 책임을 설명하는 작업 명칭이며, 최종 메뉴명·탭·화면 분할을 확정하지 않는다. 탐색 항목의 시각 디자인, 메뉴 배치, 목록의 필드·필터·정렬, 상세 화면의 정보 구성은 후속 작업에서 다룬다. 역할과 소속 부서는 세션에서 제공된다는 전제를 따르며, 로그인·계정 관리 화면은 이 범위에 포함하지 않는다.

#### 공통 탐색 대상의 책임

| 탐색 대상 | 책임 | 포함하지 않는 책임 |
|---|---|---|
| 홈 | 현재 역할이 바로 처리하거나 확인해야 할 상황을 요약해 `내 할 일` 또는 필요한 의뢰 상세로 보낸다. 역할별 첫 진입점이다. | 전체 의뢰의 완전한 목록, 상태별 전체 작업 처리, 의뢰서 내용의 편집·판단을 맡지 않는다. |
| 내 할 일 | 업무정의서 3.5의 현재 처리 대상을 역할별로 모아, 다음 행동이 필요한 의뢰로 들어가는 목록이다. | 조회만 가능한 의뢰나 이미 다른 역할이 다음 처리를 맡은 의뢰를 할 일로 넣지 않는다. |
| 의뢰함 | 역할의 조회 범위 안에서 의뢰를 찾아 상태·진행 상황을 확인하고 상세로 들어가는 목록이다. 현재 처리 대상이 아니어도 포함할 수 있다. | 할 일 우선순위나 업무 행위 권한을 대신 결정하지 않는다. |
| 의뢰 상세 | 하나의 의뢰에 대해 상태, 현재 처리자, 이력과 역할·상태가 허용하는 업무 행위를 연결하는 기준점이다. 상태 변화 뒤에는 다음 처리자의 `내 할 일` 또는 조회·대기 상태로 이어진다. | 별도의 목록 탐색이나 역할별 업무 우선순위 결정을 맡지 않는다. |

공통 이동의 책임은 `홈 → 내 할 일 또는 의뢰함 → 의뢰 상세`이다. 의뢰자에게만 `홈 → 새 의뢰 시작 → 작성 중 상세`의 병렬 진입 경로가 있다. 의뢰 상세에서 업무 행위가 완료되면 이전 처리자는 해당 의뢰를 조회·대기하고, 다음 처리자에게 할 일이 생기는 경우 그 역할의 `내 할 일`에서 이어진다. 취소 요청 대기와 관리자 확인 대기에서는 현재 처리자인 관리자가 상세에서 각각 승인·거절 또는 해석 계속·담당자 배정·재보완 요청을 처리하며, 의뢰자와 담당자는 조회·대기한다.

#### 역할별 첫 화면과 목록 범위

| 역할 | 첫 화면의 목적 | 내 할 일에 모이는 대상 | 의뢰함의 조회 범위 |
|---|---|---|---|
| 의뢰자 | 새 의뢰를 시작해 `작성 중` 상세로 들어가거나, 작성 중 의뢰를 이어 작성하고 보완·결과 확인처럼 본인 응답이 필요한 의뢰를 빠르게 찾는다. 다른 처리자가 진행 중인 내 의뢰는 현황 확인으로 연결한다. | `작성 중`, `보완 필요`, `해석 중 보완 필요`, `결과 확인 필요` | 본인 의뢰와 같은 소속 부서 의뢰를 조회한다. 같은 부서의 다른 의뢰자가 만든 의뢰는 조회만 한다. 한 번도 제출하지 않은 의뢰와 제출 전 취소 의뢰는 작성자만 조회한다. |
| 해석관리자 | 검토, 취소 요청, 관리자 확인, 관리자 보류처럼 관리자의 판단이 멈춰 있는 의뢰를 빠르게 찾는다. | `검토 중`, 취소 요청 대기, `해석 진행 중(관리자 확인 대기)`, 관리자가 보류한 `보류` | 한 번 이상 제출된 전체 의뢰를 조회한다. 한 번도 제출하지 않은 의뢰와 제출 전 취소 의뢰는 조회하지 않는다. |
| 해석담당자 | 배정된 해석을 시작·재개하거나, 수락·거절이 필요한 진행 중 변경 요청을 빠르게 찾는다. | 본인에게 배정된 일반 `해석 진행 중`, 진행 중 변경 수락 대기, 본인이 보류한 `보류` | 본인에게 배정된 의뢰를 조회한다. 관리자 확인 대기 의뢰는 배정되어도 조회·대기 대상이며 할 일에는 넣지 않는다. |

같은 상태라도 대기 요청의 종류와 보류한 사람에 따라 `내 할 일`의 역할이 달라진다. 예를 들어 취소 요청 대기는 관리자에게만, 관리자 확인 대기는 관리자에게만, 담당자가 보류한 의뢰는 해당 담당자에게만, 관리자가 보류한 의뢰는 관리자에게만 들어간다.

#### 역할별 내 할 일의 업무 분류 기준

`내 할 일`은 역할별 현재 처리 대상을 업무 종류로 구분한다. 이 분류는 무엇을 처리해야 하는지 구분하는 기준이며, 하위 메뉴·탭·섹션의 이름과 배치는 2.2~2.4에서 정한다.

| 역할 | 업무 분류 | 포함 상태 또는 대기 |
|---|---|---|
| 의뢰자 | 작성 | `작성 중` |
| 의뢰자 | 보완 | `보완 필요`, `해석 중 보완 필요` |
| 의뢰자 | 결과 확인 | `결과 확인 필요` |
| 해석관리자 | 검토 | `검토 중` |
| 해석관리자 | 취소 요청 처리 | 취소 요청 대기 |
| 해석관리자 | 해석 계속 확인 | `해석 진행 중(관리자 확인 대기)` |
| 해석관리자 | 관리자 보류 | 관리자가 보류한 `보류` |
| 해석담당자 | 해석 진행 | 본인에게 배정된 일반 `해석 진행 중` |
| 해석담당자 | 변경 요청 판단 | 진행 중 변경 수락 대기 |
| 해석담당자 | 담당자 보류 | 본인이 보류한 `보류` |

#### 목록과 상세의 권한 경계

- `내 할 일`은 행위 책임을 기준으로 하고, `의뢰함`은 조회 권한을 기준으로 한다. 같은 의뢰가 두 목록에 함께 보일 수 있으나, 역할이 수행할 수 없는 업무 행위는 상세에서 제공하지 않는다.
- 다른 역할이 다음 처리를 맡은 상태는 의뢰자·관리자·담당자에게 각각 조회·대기 대상으로 보일 수 있으나, 현재 처리자의 할 일과 혼동하지 않는다.
- 종료 상태는 역할의 조회 범위 안에서만 상세를 열람한다. 담당자는 배정 이력이 있는 `완료`와 배정 후 `취소`만 조회하며, `반려`와 배정 전 `취소`는 담당자 대상이 아니다.
- `G-30`, `G-31`이 정해지기 전에는 재배정과 대기 요청이 겹친 의뢰의 다음 처리자를 특정 목록에 확정해 넣지 않는다. 상세에서는 확인 필요 상태임을 유지한다.
